## Reference

It used to write `json.dumps(type)`, which turned `[1,2]` into `[1, 2]`. The pipeline already used the raw text, so the two would have disagreed on r2 for any non-string `type` other than F22's `[1]`.

New `raw_value(text, key)` (+20 lines): it walks the top-level keys with `json.decoder.scanstring` and `JSONDecoder.raw_decode`, and returns the exact text of the value. It's only called for a non-string `type`, which is rare.

## G31 (OPEN, raised by the reference agent): repeated keys

The spec doesn't say what happens when a key appears twice in one object (`{"id":"1",...,"id":"2"}`). The reference follows Python's `json.loads`: the **last** one wins, for every field, and `raw_value` matches that. Other parsers (e.g. some streaming ones) keep the first, or reject the line.

**Recommendation:** last wins (RFC 8259 leaves it undefined, but this is the most common behaviour), stated in §2. Rejecting as Q1 is the alternative, if Steven prefers to treat such lines as malformed.
