# AGENTS.md: one shared orientation file for every agent

**Files:** `AGENTS.md` (new), `.github/copilot-instructions.md` (cut down to a pointer).

**Why.** Agents were filling gaps by guessing ("ghosting"):
- Copilot committed fixtures into the pipeline agent's checkout.
- It wrote a one-element `requested_hours`.
- Earlier, agents worked in the wrong files.

The facts they needed were spread across `GEMINI.md`, the briefs, `fixtures/README.md` and the specs. `AGENTS.md` is the cross-tool convention: Codex, Copilot's coding agent and Cursor read it automatically, and other agents can be pointed at it.

**What it holds:**
- what the project is, and how correctness is proved
- the order of authority (spec 01 → 02 → SPEC-GAPS → brief) and what to do when the spec is silent
- a **role table**: who writes what, who never reads what, and each role's checkout and branch
- the repo layout, and every command, including both CLIs' arguments
- a "facts agents get wrong" list:
  - the output contract
  - `requested_hours` as an `[h, h]` pair
  - hand-derived expected outputs
  - hours not zero-padded in file names
  - truncated gzip
  - the manifest rules
  - where data lives
  - iCloud duplicates
- Steven's working rules, and a read order for saving tokens

It contains nothing about how either implementation works internally, so every role can read it.

**`copilot-instructions.md`.** It now only points to `AGENTS.md` and sets Copilot's default helper role, so the same rules aren't attached twice. Copilot Free's chat quota counts requests, not tokens, so the longer `AGENTS.md` costs context, not quota.

**Not changed:** `GEMINI.md` stays as it is for now. It overlaps with `AGENTS.md`, and could become a short pointer if Gemini comes back into use.
